# Бизнес-мониторинг

Бизнес-мониторинг отслеживает прохождение экземпляра бизнес-процесса — заказа, регистрации, платежа — через этапы по общему идентификатору. Этапы собираются из данных, которые платформа уже получает: APM-транзакций, распределённых трассировок, браузерных событий, записей 1С. Отдельная инструментация приложений не требуется.

Модуль отвечает на вопросы в терминах бизнеса — «сколько заказов дошло до оплаты, где потерялись остальные и почему» — а не в терминах инфраструктуры.

## Как это работает

Конфигурация состоит из двух уровней.

**Бизнес-система** описывает источники данных: откуда брать события, по какому идентификатору они собираются в один экземпляр и как связываются идентификаторы разных источников. Настраивается один раз на систему-источник — например, «заказы через интернет-магазин, SAP и 1С ERP».

**Бизнес-процесс** описывает последовательность шагов внутри бизнес-системы: условие, по которому событие считается прохождением шага, и порог, после которого экземпляр считается зависшим. Порядок шагов строгий.

Дальше платформа собирает события каждого экземпляра по его идентификатору в единую хронологию и строит поверх неё воронку, списки экземпляров, распределение времени прохождения и классификацию причин отвала. Из любого списка можно провалиться до конкретного экземпляра, а из него — до трассировки или браузерной сессии.

## Возможности

- [Бизнес-система](/modules/business-monitoring/setup.md#Бизнес-система) — источники событий и связывание идентификаторов между ними, со встроенной системой для веб-приложений
- [Конструктор бизнес-процессов](/modules/business-monitoring/setup.md#Настройка-бизнес-процесса) — карта реальных переходов, форма шагов с подсказками из данных, пороги зависания и правила причин остановки
- [Сводка по всем процессам](/modules/business-monitoring/guide.md#Оценить-состояние-бизнес-процессов) — экземпляры, доля завершённых, среднее и медианное время, сравнение с предыдущим периодом
- [Воронка бизнес-процесса](/modules/business-monitoring/guide.md#Найти-шаг-с-наибольшими-потерями) — сколько экземпляров дошло до каждого шага, перепады между шагами, состояние задействованных сервисов
- [Классификация причин отвала](/modules/business-monitoring/guide.md#Разобрать-причины-незавершённых-сессий) — почему экземпляры не дошли до конца: атрибут последнего шага, известный сбой, вероятный сбой, зависание
- [Операционный контроль](/modules/business-monitoring/guide.md#Найти-зависшие-экземпляры) — где сейчас находятся экземпляры и какие из них стоят дольше допустимого
- [Анализ времени прохождения](/modules/business-monitoring/guide.md#Проанализировать-время-прохождения) — тренд среднего и медианы, тепловая карта по шагам, распределение длительностей, самые долгие экземпляры
- [Разбор отдельного экземпляра](/modules/business-monitoring/guide.md#Разобрать-отдельный-экземпляр) — хронология шагов с переходом в распределённую трассировку и браузерную сессию
- [Пользовательские дашборды](/modules/business-monitoring/setup.md#Пользовательские-дашборды) — панели бизнес-мониторинга переносятся в обычный дашборд Grafana, рядом с другими данными клиента
- Доступ к данным бизнес-процессов через [MCP](/modules/mcp.md) — воронка, причины отвала, зависшие экземпляры и правка конфигурации из языковой модели

## Планируемые возможности

- Оповещения по бизнес-процессам — алерты на падение конверсии, зависания и рост времени прохождения
- Ускорение расчётов на больших объёмах данных
