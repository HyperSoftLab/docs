# Установка агента мониторинга кластера 1С (Docker Compose)

Данный документ описывает процесс установки и настройки агента мониторинга кластера 1С (GMonit 1C JVM Agent) с использованием Docker Compose.

**Целевая среда:** Linux-сервер с Docker и Docker Compose (может быть как отдельная ВМ, так и сервер 1С).

> ⚠️ **ВАЖНЫЕ УСЛОВИЯ:**
> * **Служба RAS** (Remote Administration Service) должна быть включена на сервере 1С.
> * **Java 21+** должна быть установлена (в Docker-образе уже включена).
> * В 1С должны быть созданы **две парольные учётные записи** — отдельная для центрального сервера и отдельная для кластера. Подробности ниже в разделе "Учётные записи 1С: важно".
> * Промежуточный **OTel Collector** (protobuf → JSON proxy) включён в комплект поставки.

### Учётные записи 1С: важно

Агент при подключении к 1С последовательно проходит **две независимые проверки авторизации**, и для них нужны **две разные учётные записи**:

| Уровень | Где создаётся в админ-консоли 1С | Поля в YAML агента |
| --- | --- | --- |
| **Администратор центрального сервера** | ПКМ по узлу самого центрального сервера (выше уровня кластера) → Свойства → закладка "Администраторы центрального сервера" | `agent-login` / `agent-password` |
| **Администратор кластера** | ПКМ по узлу конкретного кластера → Свойства → закладка "Администраторы кластера" | `clusters[].login` / `clusters[].password` |

**Жёсткие требования к обеим учётным записям:**

* **Тип авторизации — только парольный.** В диалоге создания учётной записи 1С снимите галку "Аутентификация операционной системой" и проставьте галку "Аутентификация паролем". Учётные записи на ОС-аутентификации **не подойдут** — агент шлёт логин/пароль, и сервер 1С такие учётные данные отклонит как неверные с обфусцированной ошибкой `AgentAdminException: Администратор кластера не аутентифицирован`.
* **Заголовок диалога создания учётки** должен явно содержать слова "**Параметры администратора центрального сервера**" или "**Параметры администратора кластера**". Это единственный надёжный способ убедиться что учётная запись создаётся на нужном уровне — внешне формы похожи.
* **Логины и пароли могут быть разные** для двух учёток (или одинаковые — на усмотрение администратора 1С). Это две независимые сущности на разных уровнях иерархии 1С.

**Как проверить что учётка работает на нужном уровне** (если есть доступ к утилите `rac` версии 8.3+):

```bash
# Проверка администратора центрального сервера
rac agent --agent-user='<<LOGIN>>' --agent-pwd='<<PWD>>' admin list <<RAS_HOST>>:<<RAS_PORT>>
# Успех — выводится список администраторов центрального сервера.
# "Администратор центрального сервера не аутентифицирован" — учётка не на этом уровне.
# "Администратор кластера не аутентифицирован" — пароль/логин неверный (по обфусцированной формулировке 1С).

# Проверка администратора кластера
rac cluster admin list --cluster-user='<<LOGIN>>' --cluster-pwd='<<PWD>>' --cluster=<<CLUSTER_ID>> <<RAS_HOST>>:<<RAS_PORT>>
# Успех — выводится список администраторов кластера. Учётка на нужном уровне.
```


## Установка и настройка

Вы получили архив `gmonit-1c-agent-bundle.tar.gz` с агентом мониторинга кластера 1С.

**Целевая среда:** Linux-сервер с Docker и Docker Compose.

### 0\. Предварительные требования

* **Docker** и **Docker Compose** установлены.
* **Сетевой доступ** от сервера с агентом до:
  * RAS-сервера 1С (порт 1545 по умолчанию)
  * Кластера 1С (порт 1541 по умолчанию)
  * GMonit Collector (порт 443)
* **Служба RAS** запущена на сервере 1С.
* **Две парольные учётные записи** созданы в 1С:
  * Администратор **центрального сервера** (закладка "Администраторы центрального сервера" в свойствах узла центрального сервера).
  * Администратор **кластера** (закладка "Администраторы кластера" в свойствах узла конкретного кластера).
  * **Обе на парольной авторизации**, не на ОС-аутентификации. Подробности и проверка через rac — см. раздел "Учётные записи 1С: важно" в начале документа.

### 1\. Распаковка архива

```bash
tar -xvzf gmonit-1c-agent-bundle.tar.gz
cd gmonit-1c-agent-bundle/
```

### 2\. Загрузка Docker-образов (оффлайн)

```bash
docker load -i gmonit-1c-jvm-agent.tar
docker load -i autoheal.tar
docker load -i otel-collector-contrib.tar
```

**Проверка:**

```bash
docker images | grep -E "gmonit-1c|autoheal|otel"
```

### 3\. Настройка подключения к 1С

Откройте файл `one_c_config.yaml` и заполните данные подключения:

```bash
nano one_c_config.yaml
```

**Замените плейсхолдеры** `<<...>>` на актуальные значения:

| Плейсхолдер | Описание | Пример |
| --- | --- | --- |
| `<<RAS_HOST>>` | IP/hostname сервера RAS | `192.168.0.176` |
| `<<RAS_PORT>>` | Порт RAS | `1545` |
| `<<AGENT_LOGIN>>` | Логин администратора **центрального сервера** (закладка "Администраторы центрального сервера", парольная авторизация) | `gmonit-srv` |
| `<<AGENT_PASSWORD>>` | Пароль администратора **центрального сервера** | `password` |
| `<<CLUSTER_HOST>>` | Hostname кластера 1С (**см. важное примечание ниже**) | `SRV-1C-ERP` |
| `<<CLUSTER_PORT>>` | Порт кластера | `1541` |
| `<<CLUSTER_LOGIN>>` | Логин администратора **кластера** (закладка "Администраторы кластера", парольная авторизация) | `gmonit-cl` |
| `<<CLUSTER_PASSWORD>>` | Пароль администратора **кластера** | `password` |

> ⚠️ **ВАЖНО: `clusters.host`** — должен совпадать с **реальным hostname сервера 1С** (как возвращает `rac cluster list`), а не с IP-адресом RAS. Если указать IP или Docker-адрес вместо hostname — агент не найдёт совпадение и вернёт пустой набор метрик.
>
> Проверить hostname: `rac cluster list <<RAS_HOST>>:<<RAS_PORT>>` → поле `host`.

**Итоговый пример:**

```yaml
host: '192.168.0.176'
port: 1545
# администратор центрального сервера
agent-login: 'gmonit-srv'
agent-password: 'password'
clusters:
  - host: 'SRV-1C-ERP'
    port: 1541
    # администратор кластера
    login: 'gmonit-cl'
    password: 'password'
```

### 4\. Настройка Docker Compose

Откройте `docker-compose.yml` и замените плейсхолдеры:

| Плейсхолдер | Описание | Пример |
| --- | --- | --- |
| `<<CONTAINER_NAME>>` | Имя контейнера (понятное) | `erp-1c-agent` |
| `<<COLLECTOR_HOST>>` | Полный хост коллектора GMonit | `collector.company.com` |

> **Примечание:** `GM_1C_AGENT_OTLP_HTTP_ENDPOINT` уже указывает на внутренний OTel Proxy (`http://otel-proxy:4318`) — менять его не нужно.

Откройте `otel-proxy.yaml` и замените плейсхолдер:

| Плейсхолдер | Описание | Пример |
| --- | --- | --- |
| `<<COLLECTOR_HOST>>` | Полный хост коллектора GMonit | `collector.company.com` |

> **Самоподписанные сертификаты:** раскомментируйте строки `NEW_RELIC_CA_BUNDLE_PATH` и volume `./ssl:/gmonit/ssl`, положите CA-сертификат в `./ssl/ca_bundle.crt`. В `otel-proxy.yaml` добавьте секцию `tls:` в exporter.

### 5\. Запуск

```bash
docker compose up -d
```

**Проверка статуса:**

```bash
docker compose ps
```

Ожидаемый результат: оба контейнера `running (healthy)`.

### 6\. Проверка корректности работы

**Просмотр логов агента:**

```bash
docker compose logs -f gmonit-1c-jvm-agent --tail=50
```

**Успешный запуск — ожидаемые строки в логах:**

```
Connected to RAS at <<RAS_HOST>>:<<RAS_PORT>>
Collecting metrics for cluster: <<CLUSTER_HOST>>
Metrics sent successfully
```

**Проверка ошибок:**

```bash
docker compose logs gmonit-1c-jvm-agent | grep -i "error\|exception\|failed"
```

### 7\. Критерии успеха

| Критерий | Как проверить |
| --- | --- |
| Контейнер запущен | `docker compose ps` → `running (healthy)` |
| Подключение к RAS | В логах нет `Connection refused` для RAS |
| Метрики кластера собираются | В логах: `Metrics sent successfully` |
| Нет ошибок аутентификации | Отсутствует `Authentication failed` |
| Данные в GMonit | UI → 1С мониторинг → кластер виден |

### 8\. Типичные ошибки и решения

| Ошибка | Причина | Решение |
| --- | --- | --- |
| `Connection refused` (RAS) | RAS не запущен или неверный адрес/порт | Проверьте: `curl -s telnet://<<RAS_HOST>>:<<RAS_PORT>>`. Убедитесь что RAS запущен |
| `Connection refused` (кластер) | Неверный хост/порт кластера | Проверьте параметры кластера в консоли администрирования 1С |
| `AgentAdminException: Администратор центрального сервера не аутентифицирован` | Поля `agent-login`/`agent-password` пустые или удалены, а на сервере 1С есть админы центрального сервера и они требуют авторизации | Заполните `agent-login`/`agent-password` парольной учётной записью из закладки "Администраторы центрального сервера" |
| `AgentAdminException: Администратор кластера не аутентифицирован` | **Обманчивая ошибка 1С — это "wrong creds", не обязательно про кластер.** Может означать: (а) неверный пароль на любом из двух уровней, (б) учётка создана не на том уровне (admin кластера вместо admin центрального сервера или наоборот), (в) учётка на ОС-авторизации (а агент шлёт пароль) | Проверьте обе учётки через `rac agent --agent-user=... admin list` (для admin центрального сервера) и `rac cluster admin list --cluster-user=...` (для admin кластера). Тип авторизации — только парольный, не ОС |
| `Authentication failed` (общая) | Неверные логин/пароль | Проверьте обе пары учётных данных. Учётки на ОС-авторизации не подойдут — нужны парольные |
| `Failed to export metrics` | OTel Proxy не может доставить метрики в GMonit Collector | Проверьте сеть: `curl -sk https://<<COLLECTOR_HOST>>/health`. Проверьте логи proxy: `docker compose logs otel-proxy` |
| `unhealthy` контейнер | Критическая ошибка JVM | Посмотрите логи: `docker compose logs gmonit-1c-jvm-agent` |
| Контейнер перезапускается | autoheal рестартит unhealthy-контейнер | Исправьте причину unhealthy. **Примечание:** healthcheck проверяет JVM, не подключение к RAS. Контейнер может быть healthy при отсутствии связи с RAS — ошибки подключения будут только в логах |

### 11\. Мониторинг нескольких кластеров

Для мониторинга **нескольких кластеров** добавьте их в `one_c_config.yaml`. Учётка администратора центрального сервера (`agent-login`/`agent-password`) одна на весь файл, а у каждого кластера своя пара `login`/`password` (учётная запись администратора этого конкретного кластера):

```yaml
host: '192.168.0.176'
port: 1545
# администратор центрального сервера - один на все кластеры в этом файле
agent-login: 'gmonit-srv'
agent-password: 'password'
clusters:
  - host: 'SRV-1C-ERP'
    port: 1541
    # администратор кластера ERP
    login: 'gmonit-cl-erp'
    password: 'password'
  - host: 'SRV-1C-BUH'
    port: 1541
    # администратор кластера БУХ
    login: 'gmonit-cl-buh'
    password: 'password'
  - host: 'SRV-1C-ZUP'
    port: 1541
    # администратор кластера ЗУП
    login: 'gmonit-cl-zup'
    password: 'password'
```

Для мониторинга **нескольких RAS-серверов** создайте отдельные экземпляры в `docker-compose.yml` с разными конфигами и container_name.
